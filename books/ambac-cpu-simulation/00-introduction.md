## この本について

この本は、『機動戦士ガンダム』の **AMBAC**（Active Mass Balance Auto Control：手足を振った反動で姿勢を変える）を出発点に、

> **二足歩行は本当にバランスが良いのか？ なぜ人は二本脚なのか？**

という問いと、

> **高価なフィジカル AI のハードウェアに対して、安価なコンピューターシミュレーションは、どこまで真実に迫れるのか？**

という問いを、剛体力学・幾何力学・制御理論・機械学習の言葉で、真面目に確かめた記録です。

筆者は実物のロボットを 1 台も持っておらず、最新世代の GPU もありません。すべての計算は、普通の PC とクラウドの CPU で行いました。コードと数値はすべて [GitHub: okamasaya/simulation_AMBAC](https://github.com/okamasaya/simulation_AMBAC) で公開しています。

動機と全体像は入口の記事（TODO: リンク）に、結果の要約は 2 本目の記事（TODO: リンク）に書きました。この本は、その**詳しい版**です。数式の導出、すべての数値、誤差の評価、そして**うまくいかなかったこと**まで載せます。

## AMBAC を試験台にする理由

AMBAC は、SF 考証として 1981 年のムック『ガンダムセンチュリー』で示されたとされる概念で、宇宙飛行士の自己回転や落下する猫と同じ原理で、物理的に成立します。試験台としての AMBAC には、次の良さがあります。

1. **基本式が 1 本**（$\dot\theta = -\Gamma(q)\cdot\dot q$）で、モデルが小さく、CPU で十分に扱える。
2. **答えが別に計算できる**。最適なループ、理論上の上限、ストークスの定理による値などで、学習・制御・校正の結果を答え合わせできる。
3. **非ホロノミック性**という、学習にとって本質的な難しさを含む。

## この本の姿勢

### 誤差を評価する

結果の数値には、できる限り次の 3 つを分けて付けます。

| 種類 | 意味 | 例 |
|---|---|---|
| 統計誤差 | 試行ごとのばらつき | 50 回の試行の標準偏差 |
| 計算誤差 | 数値計算の精度 | 時間刻み、積分法、最適化の収束条件 |
| 系統誤差 | 仮定や装置の癖による偏り | 総質量の仮定、ジャイロのバイアスのドリフト |

素粒子実験の流儀です。後発が存在感を出すには、科学的に正しく、他の人がやっていないことをするしかありません。誤差を評価する姿勢が、結果の正しさを支えます。第 11 章では、この姿勢のおかげで「誤差約 2%」の正体が**推定法ではなく、仮想の実機自身の積分法**だったと分かった経緯を書いています。

### 失敗を記録する

成功した結果だけでなく、うまくいかなかった試みとその理由を残します。先行研究と同じ形で失敗していれば、それは自分の仮説やロジックが同じ道筋をたどっている証拠になり、先行研究に追いつくための足場になります。第 12 章にまとめ、各章の中にも失敗と修正をそのまま残しています。

### ガンダムは「動機」として

技術の話を背骨にして、AMBAC やガンダムの設定は「なぜそれを確かめたいのか」を語る場面で登場します。作品の技術（マグネットコーティング、ムーバブルフレーム）と結果の対応は、示唆にとどめます。

## 用語と記号

| 記号 | 意味 |
|---|---|
| $\theta$ | 胴体の姿勢角 |
| $\bm q$ | 関節角のベクトル |
| $L$ | 全角運動量 |
| $A(\bm q)$ | 形を固めたときの系全体の慣性モーメント |
| $\bm\Gamma(\bm q) = \bm B/A$ | 機械的接続 |
| $F$ | 接続の曲率（$\partial\Gamma_2/\partial q_1 - \partial\Gamma_1/\partial q_2$） |
| $s$ | 相似に大きくしたときの倍率 |
| σ、pull | 推定の誤差、（推定値 − 正解）/ σ |

## 動かしてみる

```bash
git clone https://github.com/okamasaya/simulation_AMBAC
cd simulation_AMBAC
pip install -r requirements.txt
cd sims && python sim01_single_arm.py && python sim02_cyclic_gait.py
```

Sim01 で「腕振り 180° での最大姿勢変化: −16.04°」と出れば正常です。シミュレーション場（MuJoCo）を動かすには `pip install -r requirements-field.txt` が必要です。画面のない環境では `MUJOCO_GL=disable`（計算だけ）または `MUJOCO_GL=osmesa` を使います。

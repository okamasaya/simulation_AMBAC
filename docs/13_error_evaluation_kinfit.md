## 13.2 図 3（校正）の誤差評価：統計・計算・系統

ユーザーの問い：「図 3 について、統計誤差・計算誤差・系統誤差を評価することは可能か」。
ユーザーの方針：**後発が存在感を出すには、科学的に正しく、他の人がやっていないことをする。誤差を評価する姿勢が正しさを立証する。**

### 最初に気づいたこと
元の 5 回の試行では、微分なしの推定 (b′) の誤差が 5 回ともプラス側にそろっていた（平均 +1.6〜2.3%、ばらつき 0.5%）。
「誤差約 2%」の大部分は、偶然のばらつきではなく系統的な偏りだった。

### 原因：仮想の実機の積分法（計算誤差が系統誤差として現れた）
- 雑音をすべて除いても +1.3〜1.8% の偏りが残った。
- 偏りは MuJoCo の時間刻みに比例した（2 ms で +5〜7%、0.5 ms で +1.2〜1.8%、0.1 ms で +0.2〜0.3%）。
- 部品表から組み立てた機体（`assembly.build`）は積分法が `implicitfast`（1 次）で、角運動量 L = 0 がわずかに保たれない
  （式 θ' = −Γ·q' からのずれは角速度の 0.02% 程度）。
  推定はこのずれを推定しにくい方向（質量・慣性の全体の大きさ、腕・脚・慣性の相関 0.99 以上）に沿って吸収し、パラメータでは 2 桁大きい偏りになる。
- 段階 1 の手作りの機体（`space.py`）は RK4 なので、段階 1 の照合では問題が出なかった。
- **積分法を RK4 にすると、0.5 ms でも雑音なしの誤差は 0.08% 以下**。
- 元の記録の「(b′) の偏りの原因は前処理」は誤りだった（(b) には当てはまる）。docs/11 と論文を修正した。

## 13.3 kinematic fit による校正（`sims/field04c_kinfit.py`）

### ユーザーの仮説
- フィジカル AI のキャリブレーションには、素粒子実験で使われる kinematic fit のようなアプローチが最適解だろう。最適解を逐次更新していく形。そのために誤差評価をし続けることが有効。
- 理想的な動き方（物理の拘束）が分かっているので、実測値や、それに近づける補正項を逐次与えれば改善するはず。
- たとえ：人の腕でボールを投げる運動は、速度差のある運動を組み合わせる。これは粒子崩壊で質量差の大きな崩壊が続く過程と似ている
  （段階的に運動量を受け渡す連鎖を、各段の拘束条件ごとに当てはめる、という見方につながる。今後の検討課題）。

### 実装
- 測った量：エンコーダの関節角 q_m（σ_q = 0.05°）、ジャイロの角速度 ω_m（σ_ω = 0.2°/s）。
- 当てはめる量：真の関節角の列 Q（約 5200 個）、パラメータ p（腕・脚の質量、胴体の慣性の倍率）、ジャイロのバイアス b。
- 拘束条件：L = 0、すなわち ω = −Γ(Q; p)·Q'（Q' は当てはめた Q の中心差分）。
- χ² = Σ‖Q − q_m‖²/σ_q² + Σ(ω_m − b + Γ(Q; p)·Q')²/σ_ω² を、疎なヤコビアンで最小化（CPU で 1 回約 50 秒）。共分散から推定ごとの σ と χ² を得る。
- 逐次更新：ループを 1 本ずつ加え、前の推定値と共分散を事前情報にする（カルマンフィルタと同じ形）。

### 結果
| | RK4（50 回） | implicitfast（20 回） |
|---|---|---|
| 誤差の平均 | −0.01 / +0.04 / +0.04% | +1.5 / +1.8 / +2.1% |
| 誤差の標準偏差 | 1.1 / 1.1 / 1.3%（(b′) より約 3 割小さい） | 1.1 / 1.2 / 1.3% |
| 推定した σ の平均 | 1.04 / 1.11 / 1.25% | 1.07 / 1.15 / 1.29% |
| pull の平均 / 標準偏差 | +0.01〜0.05 / 1.04〜1.05 | +1.4〜1.6 / 1.10〜1.11 |
| |pull| < 1 の割合 | 66〜68% | 30〜40% |
| χ²/ndf | 0.997 ± 0.032 | 1.003 ± 0.034 |

- **推定ごとの誤差 σ が正しく見積もられる**（pull が N(0, 1)）。実機で正解が分からなくても、1 回の校正でその値をどこまで信じてよいかを示せる。
- 逐次更新では σ が 1.8% → 1.0% と縮み、最終値は一括の当てはめと 0.23% 以内で一致した。
- **限界**：積分法の系統誤差は pull を +1.5σ ずらすが、χ² の p 値は一様のままで、当てはまりの良さからは検出できない。
  ずれが推定しにくい方向に吸収されるため。χ² だけに頼らず、正解の分かっている照合（RK4 と implicitfast の比較など）と組み合わせ、誤差を評価し続ける必要がある。

図：`figures/field/field04c_kinfit.png`、数値：`data/field04c_summary.txt`。

## 13.4 学んだこと

1. **仮想の実機（シミュレータ）自身が系統誤差の源になる。** 保存則など答えの分かっている量で、仮想の実機の数値設定を先に検証する。
2. **推定しにくい方向は、小さな誤差を大きく拡大し、しかも χ² に現れない。** 相関行列と pull を見る。
3. **誤差の原因を一度決めつけると、取り違える**（今回、当初は偏りを前処理だけに帰していた）。原因は 1 つずつ切り分けて確かめる。
4. **拘束条件つきの当てはめ（kinematic fit）は、推定値とその誤差を同時に与え、逐次更新できる**。フィジカル AI の校正の枠組みとして有望。

## 13.7 番外編の解析：アルミ棒 + iPhone 2 台（`sims/bangai01_bar_imu.py`、2026-11-26）

棒（20 × 20 × 2.0 t、1 m、約 204 g）はまだ買っていないので、先に解析を作り、正解の分かっている合成データで確かめた。
合成データは phyphox の書き出しと同じ形の CSV（`data/bangai01/synthetic_*`）で、実測と同じ読み込み・解析の経路を通る。
雑音は AR(1)（ジャイロ 4 mrad/s・ρ = 0.5、加速度 0.015 m/s²・ρ = 0.3）、サンプリングの揺らぎ 2%・欠落 0.2%、バイアス、2 台目の裏返しと目盛り（−1.002）、時計のずれ（0.1〜0.6 s）と歩度（20 ppm）、時計の大まかな合わせ（meta/time.csv）の誤差 30 ms を入れた。いずれも仮定で、実測の静止区間で置き換える。

### 方法

- **1 層目（式）**：部品表から I・M・d、周期は楕円積分で厳密に。部品表の誤差は、ヤコビアン（入力ごとの寄与）とモンテカルロ（非線形の確認）の両方で伝搬する。
- **2 層目（MuJoCo）**：同じ部品表を 1 つの剛体に組み立て、iPhone の位置に仮想のジャイロを置く。
- **実験 A（振り子）**：2 台のジャイロに、θ'' = −ω0² sin θ − 2γθ' − βθ'|θ'| の解を、校正値（b1, b2, s2, τ2, κ2）と同時に当てはめる。雑音の時間相関は静止区間の ρ で白色化する（GLS）。数周期ずつ、前の区間の推定値と共分散を事前情報にして逐次更新する。照合のため、零点の時刻を振幅の補正つきで直線に当てはめる方法も並べる。
- **実験 B（回転）**：各時刻の ω を未知数（約 2000 個）にし、ジャイロ 2 台・加速度 2 台（f = −ω²r + b + 傾きによる重力）と、ω の滑らかさの事前情報、静止区間のバイアスを同時に当てはめる（field04c と同じ考え方）。
- **系統誤差**：解析の選択を 1 つずつ変えたずれ。部分集合のずれは Barlow の基準（2σ 超）で有意なものだけ数える。決められない量（時計の歩度 ±50 ppm、ジャイロ・加速度の目盛り ±0.5%）は仮定として別に示す。

### 結果（合成データ。数値は `data/bangai01_summary.txt`）

- **2 層目**：I は式と MuJoCo で 6.7 × 10⁻¹⁶ の差。振幅 10° の周期の誤差は RK4（0.1〜2 ms）で 10⁻¹¹ 以下、implicitfast は 0.5 ms で 1.4 × 10⁻⁷、2 ms で 2.2 × 10⁻⁶。**本編（段階 4）と違い、積分法はこの実験では効かない。** 振り子の周期は、角運動量の保存のような「推定しにくい方向で拡大される量」を含まないため。
- **実験 A**：T0 の統計誤差 18 µs（0.0011%）。零点の方法（71 µs）より 4 倍良い。系統は 100 µs で、時計の歩度の仮定（85 µs）とジャイロの目盛り（+1% で 53 µs、非線形の補正を通して効く）が主。予測の誤差は 2.4 ms（0.14%）で、**測定より 20 倍以上粗い。** 主因は iPhone の重心のずれの仮定（±3 mm で 2.0 ms）。実測の前に、iPhone の重心を測っておく。
- **MuJoCo の仮想の IMU で作った合成データ**を同じ解析にかけると、T0 は組み立てた機体と pull −0.54 で一致。
- **toy MC（60 回）**：振り子の T0 の pull は平均 −0.04 ± 0.11、標準偏差 0.88 ± 0.08。**雑音の相関を無視（OLS）すると 1.50 ± 0.14**、つまり誤差を 1.5 分の 1 に過小評価する。零点の方法は平均 −0.58 ± 0.13 とわずかに偏る（ピークから求める振幅の、減衰による偏りと考えられる。未確認）。回転の pull の標準偏差は r1 1.13、r2 1.01、s2 1.11、r2/r1 1.22（各 ± 0.1）。r2/r1 はやや広い（2σ）。
- **回転の素朴な回帰**（f 対 ω1² の直線）は r1 を平均 +1.3 mm 偏らせる。各時刻の ω を未知数にする当てはめで解消。
- **回転の r の系統**は、決められない目盛りの誤差が支配的（ジャイロ ±0.5% → r に 2 倍で ±3〜9 mm、加速度 ±0.5% → ±1.5〜4.5 mm）。2 台の位置を入れ替えた記録を足せば、比 r2/r1 から目盛りが打ち消せる（次の課題）。

### 残っていること

- 実物の雑音が AR(1) で表せるかは、実測の静止区間の自己相関で確かめる。
- 合成データの例 1 つで τ2 の pull −2.0、κ2 が +46 ± 10 ppm（正解 20 ppm）。toy MC の τ2 の pull の平均は +0.19 ± 0.11 で偏りは見えないので、この 1 例の揺らぎと考えるが、κ と τ の相関を含めて実測で確かめる。
- r2/r1 の pull の幅 1.22 ± 0.11。回転の合成データの例 1 つで r2 の pull +3.0（傾きの項を入れない場合との差が 1.7 mm と大きく、傾きの模型 C cos φ + S sin φ の φ を 1 台目のジャイロの積分で近似していることが疑わしい）。
- 回転の χ²/ndf は 0.92（未知の ω が事前情報で縛られるので、自由度は実効的なパラメータの数で数えた）。1 を下回る理由は未確認。
- phyphox の列名は、実物の最初の CSV で確かめる（列名はゆるく照合している）。

## 13.2 図 3（校正）の誤差評価：統計・計算・系統

ユーザーの問い：「図 3 について、統計誤差・計算誤差・系統誤差を評価することは可能か」。
ユーザーの方針：**後発が存在感を出すには、科学的に正しく、他の人がやっていないことをする。誤差を評価する姿勢が正しさを立証する。**

### 最初に気づいたこと
元の 5 回の試行では、微分なしの推定 (b′) の誤差が 5 回ともプラス側にそろっていた（平均 +1.6〜2.3%、ばらつき 0.5%）。
「誤差約 2%」の大部分は、偶然のばらつきではなく系統的な偏りだった。

### 原因：仮想の実機の積分法（計算誤差が系統誤差として現れた）
- 雑音をすべて除いても +1.3〜1.8% の偏りが残った。
- 偏りは MuJoCo の時間刻みに比例した（2 ms で +5〜7%、0.5 ms で +1.2〜1.8%、0.1 ms で +0.2〜0.3%）。
- 部品表から組み立てた機体（`assembly.build`）は積分法が `implicitfast`（1 次）で、角運動量 L = 0 がわずかに保たれない
  （式 θ' = −Γ·q' からのずれは角速度の 0.02% 程度）。
  推定はこのずれを推定しにくい方向（質量・慣性の全体の大きさ、腕・脚・慣性の相関 0.99 以上）に沿って吸収し、パラメータでは 2 桁大きい偏りになる。
- 段階 1 の手作りの機体（`space.py`）は RK4 なので、段階 1 の照合では問題が出なかった。
- **積分法を RK4 にすると、0.5 ms でも雑音なしの誤差は 0.08% 以下**。
- 元の記録の「(b′) の偏りの原因は前処理」は誤りだった（(b) には当てはまる）。docs/11 と論文を修正した。

### 誤差の内訳（`sims/field04b_error_budget.py`、RK4 を基準）

## 13.3 kinematic fit による校正（`sims/field04c_kinfit.py`）

### ユーザーの仮説
- フィジカル AI のキャリブレーションには、素粒子実験で使われる kinematic fit のようなアプローチが最適解だろう。最適解を逐次更新していく形。そのために誤差評価をし続けることが有効。
- 理想的な動き方（物理の拘束）が分かっているので、実測値や、それに近づける補正項を逐次与えれば改善するはず。
- たとえ：人の腕でボールを投げる運動は、速度差のある運動を組み合わせる。これは粒子崩壊で質量差の大きな崩壊が続く過程と似ている
  （段階的に運動量を受け渡す連鎖を、各段の拘束条件ごとに当てはめる、という見方につながる。今後の検討課題）。

### 実装
- 測った量：エンコーダの関節角 q_m（σ_q = 0.05°）、ジャイロの角速度 ω_m（σ_ω = 0.2°/s）。
- 当てはめる量：真の関節角の列 Q（約 5200 個）、パラメータ p（腕・脚の質量、胴体の慣性の倍率）、ジャイロのバイアス b。
- 拘束条件：L = 0、すなわち ω = −Γ(Q; p)·Q'（Q' は当てはめた Q の中心差分）。
- χ² = Σ‖Q − q_m‖²/σ_q² + Σ(ω_m − b + Γ(Q; p)·Q')²/σ_ω² を、疎なヤコビアンで最小化（CPU で 1 回約 50 秒）。共分散から推定ごとの σ と χ² を得る。
- 逐次更新：ループを 1 本ずつ加え、前の推定値と共分散を事前情報にする（カルマンフィルタと同じ形）。

### 結果
| | RK4（50 回） | implicitfast（20 回） |
|---|---|---|
| 誤差の平均 | −0.01 / +0.04 / +0.04% | +1.5 / +1.8 / +2.1% |
| 誤差の標準偏差 | 1.1 / 1.1 / 1.3%（(b′) より約 3 割小さい） | 1.1 / 1.2 / 1.3% |
| 推定した σ の平均 | 1.04 / 1.11 / 1.25% | 1.07 / 1.15 / 1.29% |
| pull の平均 / 標準偏差 | +0.01〜0.05 / 1.04〜1.05 | +1.4〜1.6 / 1.10〜1.11 |
| |pull| < 1 の割合 | 66〜68% | 30〜40% |
| χ²/ndf | 0.997 ± 0.032 | 1.003 ± 0.034 |

- **推定ごとの誤差 σ が正しく見積もられる**（pull が N(0, 1)）。実機で正解が分からなくても、1 回の校正でその値をどこまで信じてよいかを示せる。
- 逐次更新では σ が 1.8% → 1.0% と縮み、最終値は一括の当てはめと 0.23% 以内で一致した。
- **限界**：積分法の系統誤差は pull を +1.5σ ずらすが、χ² の p 値は一様のままで、当てはまりの良さからは検出できない。
  ずれが推定しにくい方向に吸収されるため。χ² だけに頼らず、正解の分かっている照合（RK4 と implicitfast の比較など）と組み合わせ、誤差を評価し続ける必要がある。

図：`figures/field/field04c_kinfit.png`、数値：`data/field04c_summary.txt`。

## 13.4 学んだこと

1. **仮想の実機（シミュレータ）自身が系統誤差の源になる。** 保存則など答えの分かっている量で、仮想の実機の数値設定を先に検証する。
2. **推定しにくい方向は、小さな誤差を大きく拡大し、しかも χ² に現れない。** 相関行列と pull を見る。
3. **誤差の原因を一度決めつけると、取り違える**（今回、当初は偏りを前処理だけに帰していた）。原因は 1 つずつ切り分けて確かめる。
4. **拘束条件つきの当てはめ（kinematic fit）は、推定値とその誤差を同時に与え、逐次更新できる**。フィジカル AI の校正の枠組みとして有望。

## 13.6 次の課題

- 拘束条件つきの当てはめに、アクチュエータ（サーボの遅れ）・摩擦の校正値を加え、地上の機体（段階 12〜17）へ広げる。
- 推定しにくい方向を外から決める独立な情報（総質量の計量、関節トルク）を拘束として加え、χ² で系統誤差を検出できるかを試す。
- 投球のような「速度差のある運動の連鎖」を、段ごとの拘束条件の連鎖として当てはめる（崩壊の連鎖の当てはめとの対応）。
- 学習法（PPO・SAC）との比較、ほかの非ホロノミック系での検証（品評の指摘）。
